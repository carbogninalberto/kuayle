# Changelog

## Unreleased

- Settings → Instance configuration can now edit startup-only settings (`ISSUE_DELETE_GRACE_PERIOD`, `PASSKEYS_ENABLED`, `PASSKEY_RP_DISPLAY_NAME`, `SSO_OIDC_DEFAULT_ROLE`, `S3_PUBLIC`, `S3_CDN_BASE_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `FORGE_WEBHOOK_BASE_URL`). Draft the values, check them with a dry run, then **Apply and restart**: the overrides are stored in the database (migration 212, merged over `.env` when the API starts), the API restarts, and the previous values return automatically if it is not healthy within 90 seconds. Secrets, connection strings, `JWT_SECRET`, `SYSADMINS`, private-network switches and variables other services read stay read-only. It needs a supervisor that restarts the API: set `RESTART_SUPERVISED=true` (the reference Compose file does). See [instance configuration](docs/self-hosting.md#instance-configuration).
- The task Files panel reads the repository lazily: opening it lists the root only, each folder is read when it is expanded, and the path filter is answered by the server. A published task is listed through GitHub's trees API instead of a downloaded archive, directories are cached in memory by their immutable git tree SHA so a new head reuses the unchanged ones, and an unpublished task is read with `git ls-tree` of one directory on its machine. `GET /agent-tasks/:taskId/files` now returns one directory (`path=`) or a search (`query=`) as `entries`, not the whole file list. See [files at a commit](BE/docs/agent-tasks.md#files-at-a-commit).
- Custom workspace roles support per-team overrides. Self-hosted installations with multiple owner memberships in one workspace must reconcile them before migration 202. The [upgrade guide](docs/self-hosting.md#before-migration-202-workspace-roles) includes a preflight query and recovery instructions.
- Settings → Instance configuration (sysadmins only) lists every variable the API reads, with its value and source; secrets show only whether they are set. `WORKFLOW_PIPELINES_ENABLED`, `DISABLE_REGISTRATION` and `BACKUP_TIMEOUT` can be changed there without a restart (migration 211). Team workflows (pipelines) are now on by default; set `WORKFLOW_PIPELINES_ENABLED=false` to keep them off. See [instance configuration](docs/self-hosting.md#instance-configuration).
